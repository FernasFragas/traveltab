# 5d — Monthly sync job

Source: `tasks/todo.md` 5d (integrator of PR 5), `tasks/plan.md` decision 4 and **Rules for Agents**, `docs/maintenance.md` "Writers' map", `docs/writers-map-contract.md` (source statuses).

## Journeys

- As the owner, I want the first crawl of every active source to start at once and resume from its cursor after a restart, so that a killed server never starts over.
- As the owner, I want one update per source per month in the off-peak window (changed posts since the cursor, then a deleted-posts sweep), so that writers' sites see little traffic.
- As a writer, I want a 403 or a robots.txt disallow to stop all requests to my site, and a takedown (`removed`) to purge my rows, so that my wishes are respected.
- As the owner, I want a deleted post dropped only when the site really no longer lists it, so that a page shift mid-sweep or a failed sweep never deletes good rows.
- As the operator, I want writes in place and no overlapping runs, so that the database stays bounded and consistent.
- As the summary job (PR 9), I want a hook that runs after the index update and the destination refresh, so that summaries see fresh data.

## Design

- `internal/writermap/sync.go`: `SyncJob` with `Run(ctx)` (one pass) and `Schedule(ctx)` (run at startup, then at 02:00 UTC daily). Ports defined in `writermap`: `SyncIndex`, `PostLister`, `CachedDestinations`, `DestinationRefresher`. `cmd/web/main.go` adapts `*sqlite.Store` and `*api.WordPressClient` to them (type conversion only).
- **Due rule per source:** crawl not finished (`LastFull` zero) → run now; otherwise only in the off-peak window (02:00–06:00 UTC) when the state is `partial` or the last finished sync was in an earlier calendar month.
- **Cursor:** latest indexed `modified` (RFC 3339), saved after every page. Listing restarts at page 1 one second before the cursor (keyset paging), so equal timestamps and mid-crawl edits can't skip posts; posts re-listed unchanged in the same run are not re-indexed.
- **Deletion:** stored ids missing from a full id sweep are re-checked by a second sweep; only ids missing from both are deleted. Any sweep error, or a sweep that lists zero ids, deletes nothing and leaves the source `partial`.
- **Lock:** in-process `sync.Mutex.TryLock`; a second `Run` returns `ErrSyncRunning`.
- **Blocked:** errors matching `BlockedErrors` (`api.ErrBlocked`, `api.ErrDisallowed`) save `blocked` in `writer_sync`; the source is never requested again.
- **Logs:** one line per source per run with host, outcome and counts; never titles or post text.

## Known gaps

- Cached destinations come back with lowercased names and countries, because that is how the cache key stores them. `Refresh` maps them to the same row, and the Wikidata query uses only coordinates and radius.
- The `cmd/web` adapters (type conversion only) have no tests of their own; the same conversions are used in `sync_test.go`.
- The lock is per process. Running more than one machine against one database would need a lock in the database.
- A `blocked` sync state is permanent. To unblock, set the source `removed` (purge) and then `active` again.
- The PR-level check against real blogs was run on 2026-10-11 at the owner's request; see **Live two-blog check** below.
