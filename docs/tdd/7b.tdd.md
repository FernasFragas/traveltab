# 7b — Day plan layer: TDD Evidence

**Source task:** `tasks/todo.md` 7b. Layer name `plan` (7f toggles it with `TravelMap.setLayerEnabled('plan', ...)`).

## User journeys

- As a traveler, I want my itinerary stops drawn as numbered green pins, so that I can see the plan on the map.
- As a traveler, I want to show one day or all days, so that a long trip stays readable.
- As a traveler regenerating or clearing a plan, I want old pins gone, so that the map never shows stale or duplicate pins.
- As a visitor without the writers' map (flag off), I want nothing to change.

## Design

- `views/itinerary_body.go.tpl` adds `data-plan-day="N"` on each day and `data-plan-stop data-name data-lat data-lon` on each stop. No endpoint or contract change.
- `public/redesign/map-dayplan.js` registers layer `plan`, reads those attributes after `htmx:afterSwap` / `htmx:historyRestore` (and on load), calls `TravelMap.updatePlan(days)`, and redraws on `travelmap:plan-updated`. It does nothing without `TravelMap` or a `[data-writers-map]` shell.
- `views/index.go.tpl` only gains the script tag.

## Bug: selected day reset by unrelated swaps

Found in the browser check: after clicking "Day 1" the choice did not stick. `report()` runs on every `htmx:afterSwap` (other cards, the place panel) and the `travelmap:plan-updated` listener always reset the day to "All".

RED (new test `keeps the selected day across unrelated swaps and an unchanged plan`):

```text
$ node --test tasks/redesign/checks/map-dayplan.test.mjs
✖ keeps the selected day across unrelated swaps and an unchanged plan
    actual: 3,
    expected: 2,
ℹ pass 9
ℹ fail 1
```

Fix: the listener ignores an update whose days equal the current ones, and resets to "All" only when the plan changes (covered by `resets to all days when the plan changes`).

