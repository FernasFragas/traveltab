## RED → GREEN

The new preview test was run against the previous fixture with a Go `-overlay` (no working-tree edit):

`go test -overlay=/private/tmp/pr8c-red-overlay.json ./cmd/design-preview -run 'TestWriterMapPreview_(TwoWriterCities|FunchalWeatherUsesCityCoordinates)' -count=1 -v` → `Funchal: no writer itinerary`; `Lisbon: no writer itinerary`; `Funchal weather identity ... Lon:-9.1393 Lat:38.7223`; `FAIL`.

With the Funchal identity and Lisbon writer fixture added:

`go test ./cmd/design-preview -run 'TestWriterMapPreview_(TwoWriterCities|FunchalWeatherUsesCityCoordinates)' -count=1 -v` → both tests and subtests `PASS`.

`node tasks/redesign/checks/pr8c-journeys.browser.mjs` → six `PASS` lines: Funchal, Lisbon and Coimbra at 375 and 1440 px. The check uses an isolated Brave session, tests keyboard controls, asserts no horizontal overflow or browser errors, and saves screenshots to [artifacts/8c](artifacts/8c/). A first run failed because the lazy map was outside the viewport; the check now reveals the map before waiting for pins. The map can use MapLibre or its Leaflet fallback.

The keyboard-only rerun found a panel focus bug at Lisbon, 1440 px. Before the fix, `node tasks/redesign/checks/pr8c-journeys.browser.mjs` printed `PANEL WAIT Lisbon 1440` with the Belém Tower panel present, `active:"<body>..."`, then `Timed out: ... document.activeElement?.matches(".map-place-panel h3")`. `map-panel.js` cleared its pending focus flag on any HTMX swap even when that swap contained no panel heading. Moving the clear after the heading check made the same command print all six `PASS` lines. This is an inference about the event ordering from the code and observed focus; the browser test verifies the user-visible focus outcome.
