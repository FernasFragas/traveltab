## Follow-up: packed `writer_names` layout (owner decision, 2026-10-11)

**Why:** the live two-blog sync (see `5d.tdd.md`) produced 54.3 MB for 884 posts, about 1.1 GB projected to ~20,400 posts against the proposed 300 MB bar. The owner chose layout F from the size probe.

**What changed** (`internal/adapters/sqlite/writerindex.go`):
- `writer_posts` gains an integer `id` (the post ref); `(host, post_id)` stays unique, and the upsert keeps the id via `RETURNING id`.
- `writer_names` is `(folded, post_ref, positions)`, `WITHOUT ROWID`, one row per post and phrase. Every occurrence is packed into `positions` as two uvarints: `start<<1 | original case`, then length. Indexed by `post_ref` for deletes.
- `writer_days` is keyed by `post_ref`, `WITHOUT ROWID`.
- `FindWriterNames` still returns one `WriterNameMatch` per occurrence, in the same order, so callers don't change. Invalid spans are rejected in Go (previously a `CHECK`), so a bad extraction still leaves the previous post in place.

**RED:** `go test ./internal/adapters/sqlite/ -run 'TestWriterIndex'`
```
--- FAIL: TestWriterIndex_RepeatedPhraseIsOneRowWithEveryPosition (0.01s)
        	Error:      	Not equal: 
        	            	expected: 2

```
**GREEN:** the same command: all 9 `TestWriterIndex_*` tests PASS. `TestWriterIndex_PurgeHostDeletesEveryRowForIt` was adapted: `writer_names` and `writer_days` no longer have a `host` column, so it checks counts and that lookups return only the other host.

**Can it fail?** Dropping the original-case bit fails `ReindexReplacesRows` and `RepeatedPhraseIsOneRowWithEveryPosition`; keeping duplicate positions fails `RepeatedPhraseIsOneRowWithEveryPosition`.

| What is guaranteed | Test | Type | Result |

| Purging a host removes its posts, names, days and sync state, and keeps other hosts | `TestWriterIndex_PurgeHostDeletesEveryRowForIt` | integration (temp SQLite) | PASS |

**Gate:** `go test -race -cover`: `sqlite` 81.4%, `writermap` 93.8%. `PATH=/tmp/traveltab-lint-bin:$PATH make test lint build`: all ok, `0 issues.`, build succeeded.

**Live result** (same two blogs, full sync, 157 s): 884 posts, 219,295 `writer_names` rows (was 436,232), 700 `writer_days` rows (unchanged). **Database 10.9 MB (was 54.3 MB)**, 9.7 MB after `VACUUM`.
