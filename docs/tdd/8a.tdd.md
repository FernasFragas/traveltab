# 8a — Resilience tests

Source: `tasks/todo.md` 8a and `tasks/plan.md` PR 8. These tests exercise existing behavior; no production code changed.

## Journeys

- As a traveler, I want the map shell, tiles, and day plan to remain usable when a cold Wikidata lookup fails, so that the places failure is reported without losing the trip.
- As a traveler, I want original writer links when summaries are absent or AI is disabled, so that I can still read the posts.
- As a traveler, I want searches to work during an interrupted sync and after its restart, so that an unfinished crawl does not erase indexed posts.
- As a traveler, I want twenty simultaneous searches for a new destination to share one base-place query, so that a burst of visits does not multiply Wikidata requests.

## Limits

- The interrupted crawl is a deterministic write failure after one indexed post, followed by a fresh job instance over the same database. The test does not kill an OS process.
- The Go route test verifies the 503 response and the page's `role="status"` outlet. The browser's exact text for that response is supplied by `public/redesign/writers-map.js`; the 8c browser journey should check the rendered message.
- Nil summaries model AI being off in the current source. PR 9 owns the `WRITERS_AI` wiring.
