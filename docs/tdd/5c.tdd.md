# 5c — WordPress client and host limiter

Source: `tasks/todo.md` 5c, `tasks/plan.md` **Delivery** / **Rules for Agents**, and the sync rules in `docs/maintenance.md` "Writers' map".

## Journeys

- As the monthly sync (5d), I want one page of changed posts at a time (`modified_after`), so that I index edits without holding a whole blog in memory.
- As the monthly sync, I want an id-only sweep, so that I can drop posts the writer deleted.
- As the summary job (PR 9), I want one post's content by id, so that I can cut passages and discard the text.
- As a writer site, I want TravelTab to identify itself, honor `robots.txt` and wait ≥1.5 s between requests across every job, so that crawling stays polite.
- As the sync, I want a 403 to be a typed `ErrBlocked`, so that I mark the source `blocked` and stop requesting it.
- As the sync, I want a page past the last one to end pagination cleanly and a timeout to be retried once, so that normal WordPress behaviour and blips don't fail a run.

## Known gaps

- Uncovered lines are the nil-client default, request-construction errors and a timer firing in `sleepContext` (the frozen-clock tests never sleep for real).
- The robots cache lives as long as the client; a robots.txt change is seen after a restart.
- The id sweep pages by WordPress's default order; a post deleted mid-sweep can shift one id onto an already-read page. 5d should confirm a "missing" id before deleting it (for example with `PostContent` → 404).
- Timeouts are retried once; 5xx and 429 are returned to the caller without retry.
