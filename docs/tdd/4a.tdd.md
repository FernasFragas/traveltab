# 4a — Wikidata nearby adapter

Source: `tasks/todo.md` 4a and `tasks/plan.md` layer 1.

## Journeys

- As a map visitor, I want visitable places near my destination, ranked by sitelinks, so that useful base pins appear even before any writer data is indexed.
- As a writer matcher, I want every named nearby Wikidata entity and its P31 types, so that a writer-mentioned municipality or other filtered place can still be matched.
- As a map visitor, I want descriptions, links, hours, and attributed photos when Wikidata and Commons have them, so that a panel can show trustworthy details without inventing missing fields.
- As a background warmer, I want provider errors and `Retry-After` cancellation returned promptly, so that a failed query does not produce a false cached success.

The SPARQL query uses one `wikibase:around` request. It requests English and Portuguese labels and aliases, P31 types, English descriptions, P18, sitelinks, English Wikipedia links, P131 area labels, and P3025 days with P8626/P8627 time item labels. The generated `planner.PlaceTypes` map selects pins; all named nearby entities remain in the gazetteer. Commons image information is requested in batches of up to 50 distinct file titles and accepted only with a safe image URL, Commons page URL, author, and license. The offline fixture uses the real QIDs for [Cabo Girão](https://www.wikidata.org/wiki/Q856866), [Madeira Airport](https://www.wikidata.org/wiki/Q639161), and [Câmara de Lobos municipality](https://www.wikidata.org/wiki/Q623736); its bindings are deliberately small and hand-curated.
